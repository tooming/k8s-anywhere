# Bump Cilium chart `1.17.18` → `1.18.12`

CHARTER **Core Values** §"Everything as code" + general hardening; RFC #917 —
architect decision 2026-07-30, ADR-0014 audit #916 resolved as **Convert**.
Cilium's `SECURITY.md` support table now marks every version `< 1.18.0` as
unsupported (verified directly, not training knowledge — ADR-0004); this
lab's `1.17.18` pin (`gitops/platform/cilium.yaml`) was on that unsupported
line. This is the exact flip condition ADR-0014's 2026-07-28 Re-evaluation
log entry (audit #772) recorded in advance. Cilium's own upgrade path is
sequential minor-by-minor, so this item is deliberately one step (`1.17.18`
→ `1.18.12`, the latest `1.18.x` patch per `git ls-remote --tags
https://github.com/cilium/cilium.git`), not the full jump to the current
`1.20.0` — a future item covers the next step once this one has landed.

## What changed

Bumped `gitops/platform/cilium.yaml`'s `targetRevision: 1.17.18` →
`1.18.12`, and rewrote its header comment to document both the original
CVE-2026-49445 pin rationale and this EOL-driven bump. Re-verified directly
at pickup time (not just RFC #917's cached read) that the `1.18.12` chart's
`values.yaml` (fetched from
`raw.githubusercontent.com/cilium/cilium/v1.18.12/install/kubernetes/cilium/values.yaml`)
still contains every key this Application's `valuesObject` sets, unchanged in
shape, versus the `v1.17.18` tag's copy: `kubeProxyReplacement`,
`prometheus.enabled`/`port`, `hubble.enabled`, `operator.replicas`/
`resources`, top-level `resources` — no schema change, safe version-only bump.

Added a new dated entry to [ADR-0014](../decisions/adr-0014-cilium-not-flannel-policy.md)'s
`## Re-evaluation log` recording the bump landing, with a new flip condition
for the next step ("revisit when `1.18.x` itself reaches end-of-support, or a
CVE lands against `1.18.12` specifically").

Updated `tests/cilium.bats`'s chart-pin assertions: the `1.17.18` assertion
now asserts `1.18.12`, and a new negative assertion guards against
regressing to the now-EOL `1.17.18` pin (mirroring the existing negative
assertion for the pre-CVE-fix `1.16.6` version) — a recurrence guard per
CLAUDE.md's bug-fix-prevents-recurrence rule.

Updated both Cilium version citations in `docs/dependency-tree.md` (the
dependency table row and the prose Cilium section) from `v1.17.18` to
`v1.18.12`.

## Rollback path

Revert `targetRevision` back to `1.17.18` — ArgoCD self-heals within its sync
interval; Cilium is a DaemonSet, so a revert re-rolls the same way the bump
did. (ADR-0004 caveat: this remote clusterless session cannot verify Cilium
continues routing pod traffic cleanly post-bump on a live cluster — that
verification requires a live-cluster session.)

`make ci` passes. No cluster access was used or required — this is a
clusterless, structural chart-pin bump; the `values.yaml` schema comparison
above was done by direct file fetch, not a live Helm render.
