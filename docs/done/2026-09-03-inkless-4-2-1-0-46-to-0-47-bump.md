# Bump Aiven Inkless broker `4.2.1-0.46` → `4.2.1-0.47`

Aiven Inkless's register row (last reviewed 2026-08-18) was due for a currency
re-check per its own numbered-release-line convention. A planner-fallback currency
sweep found `inkless-release-0.47` published (2026-08-19).

Verified directly (not assumed, ADR-0004): GitHub's release list confirms
`inkless-release-0.47` as the newest release. Confirmed the exact image tag
`ghcr.io/aiven/inkless:4.2.1-0.47` is real and pullable via the same anonymous-token
GHCR manifest query the original 2026-08-18 pinning entry used — `GET
/v2/aiven/inkless/manifests/4.2.1-0.47` with an `Accept` header covering
`application/vnd.oci.image.index.v1+json` (a first attempt using only
`application/vnd.docker.distribution.manifest.v2+json` returned a misleading 404
since this is a multi-arch manifest list, not a single-arch manifest; re-tried with
the broader `Accept` header and confirmed 200, cross-checked against the known-good
`4.2.1-0.46` tag returning the same 200 to validate the query methodology).

## Release contents

No named CVE this release. Real bug fixes (retention-enforcement throughput pacing,
control-plane row repair, ISR-state clearing after a classic-to-diskless switch,
bounded error-message/logging sizes) and new metrics/observability additions.

## Caveat flagged, not silently absorbed

The release notes state "Three PostgreSQL migrations included; migrations V24 and
V25 require table-level locks" against the `postgres:17` batch-coordinator ADR-0015's
Stack table already names. This session could not confirm whether Inkless runs these
migrations automatically on broker startup or needs a human-triggered step — neither
this repo's docs nor Inkless's public README document its migration-execution
mechanism. Since Inkless is on-demand and not currently running in any live cluster
this session can affect, this bump carries zero live-cluster blast radius today — but
the next `make inkless-up` needs to watch the broker's startup logs for migration
completion before assuming the bump is safe. **A `[Manual step]` issue is filed for
this** (see below) rather than left only in the ADR entry.

## ADR-0004 caveat

This remote, clusterless session verified the release existence and published-image
facts directly, but cannot verify the broker starts cleanly and the PostgreSQL
migrations complete successfully on a live cluster. Rollback is a one-line image-tag
revert; no data loss risk from the revert itself (Inkless's real state lives in
Garage S3 + the `postgres:17` PVC), though a completed forward migration isn't
automatically reversed by an image downgrade — a real consideration if a live `make
inkless-up` hits trouble post-bump, noted in the manual-step issue.

`make ci` passes green (lint/readme-check/lab-ui-check/all drift detectors including
`dependency-register-check.sh` — bats/kustomize/terraform tools aren't installed in
this clusterless session; the full suite runs in GitHub Actions).
