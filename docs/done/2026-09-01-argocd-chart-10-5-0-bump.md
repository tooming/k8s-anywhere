# Bump ArgoCD Helm chart `10.4.0` → `10.5.0` (appVersion `v3.5.1` → `v3.5.2`)

(CHARTER **Core Values** §"Everything as code" + general dependency hygiene; upgrade-drafter fallback, executor.prompt.md STEP 6b — this run's sixth cycle, found via the digest written the prior cycle: [docs/industry/2026-W36-digest.md](../industry/2026-W36-digest.md) flagged the Terraform-bootstrapped ArgoCD chart as one release behind and deliberately left it un-bumped in that digest's own PR to keep it singular. The "Now / next" lane remained fully gated (two GitLab→Forgejo migration items + the capstone-`Deployment`-removal item, all blocked on unconfirmed live-cluster prerequisites — issues #633/#1229/#1345, unchanged since 2026-08-25) and PLANNER found no ungroomed intake or un-RFC'd 🟡 item.)

- Component: `argo-cd` Helm chart, `argoproj.github.io/argo-helm` repo (Terraform-bootstrap seam, ADR-0001 — `infra/modules/argocd/`, not gitops-managed). No ADR pins ArgoCD's chart/app version specifically.
- From → To: chart `10.4.0` (appVersion `v3.5.1`) → chart `10.5.0` (appVersion `v3.5.2`).
- Why this version: verified directly (not assumed, ADR-0004) against the real chart source (`raw.githubusercontent.com/argoproj/argo-helm/argo-cd-10.5.0/charts/argo-cd/Chart.yaml`) — `version: 10.5.0`, `appVersion: v3.5.2`. Same major line (`10.x` → `10.x`), a routine minor bump, in scope for this routine per its own "no major bumps" rule.
- **Schema compatibility check:** an initial broad fetch of the chart's `values.yaml` at `10.5.0` reported `applicationSet.*`, `repoServer.*`, and `notifications.*` as missing — this was a fetch-truncation artifact (the file is large), not a real finding; a second, targeted fetch confirmed all of them present with unchanged structure. Every path this repo's `infra/modules/argocd/values.yaml` sets — `global.{domain,securityContext,networkPolicy.create}`, `configs.{params,cm}`, `dex.enabled`, `notifications.enabled`, `applicationSet.{enabled,metrics,resources,livenessProbe,readinessProbe}`, `controller.{metrics,resources,readinessProbe}`, `repoServer.{metrics,env,resources,livenessProbe,readinessProbe}`, `server.{metrics,resources,livenessProbe,readinessProbe}`, `redis.resources`, `redisSecretInit.securityContext` — is present and structurally unchanged at `10.5.0`.
- **What changed vs. what didn't:** this bumps the Helm *chart* (templates/schema + appVersion) only. No `global.image.tag` override exists in this repo's `values.yaml` anymore (removed by a prior janitor cleanup, 2026-08-05) — the chart's own default resolves to `.Chart.AppVersion`, so this bump automatically deploys ArgoCD `v3.5.2` on next `terraform apply`, no separate image-tag edit needed.
- Updated `infra/modules/argocd/variables.tf`'s `chart_version` default + description, both `infra/live/{local,oracle}/argocd/terragrunt.hcl`'s `chart_version` inputs (same edit surface as any other bump — the module default plus every terragrunt.hcl that sets it, per this repo's own "separate enumeration surface" precedent), `tests/argocd-chart-pin.bats`'s three pin assertions (retitled, negative assertion extended to include the superseded `10.4.0`), and `docs/dependency-register.md`'s ArgoCD row.
- **ADR-0004 caveat:** this remote clusterless session cannot verify `terraform apply`/`helm upgrade` actually reconciles cleanly against the new chart version on a live cluster (no cluster reachable from this session). Rollback path: revert the three `chart_version` values back to `10.4.0`.
