# Bump k3s `v1.36.3+k3s1` → `v1.36.4+k3s1` on both backends

k3s's register row (last reviewed 2026-08-20) was due for a currency re-check per
ADR-0030's own flip condition. A planner-fallback currency sweep found `v1.36.4+k3s1`
published (2026-08-27).

Verified directly (not assumed, ADR-0004): GitHub's release notes for `v1.36.4+k3s1`
list "Backports for 2026-08" and a `containerd` bump to `v2.3.4-k3s1.36`. A separate
summarization of the releases *list* page claimed this backport mitigates
CVE-2025-54410 via a `docker/docker` v25.0.13 dependency bump — but the release's own
detailed notes do **not** cite any CVE or Security heading, so this is flagged as
unconfirmed rather than asserted: a WebSearch independently confirmed CVE-2025-54410
is real (Docker Engine network-isolation bypass on `firewalld` reload, CVSS 3.3 Low,
fixed in Moby 25.0.13), but this describes the actual Docker Engine daemon, which k3s
does not run (k3s uses `containerd` directly). Even if `github.com/docker/docker` is
vendored as a Go dependency somewhere in k3s's own tooling, the actual exploitable
surface this CVE describes likely doesn't apply here either way. Also confirmed: this
release bumps the bundled Traefik chart to `v40.x` with a breaking provider-name
change — irrelevant here since this lab's k3s config passes `--disable=traefik` on
both backends per ADR-0008 (Envoy Gateway, not Traefik). Docker Hub confirms
`rancher/k3s:v1.36.4-k3s1` is a real, published, active-status tag (last updated
2026-08-27T15:55:33Z).

## What changed

- `infra/modules/k3d-cluster/k3d-config.yaml.tftpl`: `image: rancher/k3s:v1.36.3-k3s1`
  → `v1.36.4-k3s1`.
- `infra/modules/oracle-k3s-cluster/cloud-init.yaml`:
  `INSTALL_K3S_VERSION=v1.36.3+k3s1` → `v1.36.4+k3s1`.
- `tests/k3s-version-pin.bats`: both per-backend pin assertions, the cross-backend
  match assertion, and the context.md documentation assertion updated.
- `docs/decisions/context.md`: "k3s v1.36.3+k3s1" citation updated to `v1.36.4+k3s1`.
- `docs/decisions/adr-0030-pin-k3s-version-explicitly.md`: new Re-evaluation log
  entry (trigger, verification, the unconfirmed-CVE honesty flag, the
  irrelevant-Traefik-breaking-change note, decision, ADR-0004 caveat, next flip
  condition).
- `docs/dependency-register.md`: k3s row updated.

## Decision: routine currency, not a confirmed security fix

Treated as "Convert (bump), routine currency" rather than asserting a security fix —
the one CVE claim traced back to a summary of the releases list page, not the
release's own detailed notes, and independently doesn't describe an exploitable
surface k3s's own runtime (containerd, not Docker Engine) actually exposes. Bumping
anyway since it's the newest stable release with no reason to hold back.

## ADR-0004 caveat

This remote, clusterless session verified the release's real existence and
published-image facts directly, but cannot verify a fresh `make up`/Terraform apply
against either backend still bootstraps cleanly on this new k3s minor patch.
Rollback is a one-line revert of both pins; ArgoCD/GitOps state is unaffected by a
k3s-version change alone since it governs only the bootstrap layer (ADR-0001).

`make ci` passes green (lint/readme-check/lab-ui-check/all drift detectors including
`dependency-register-check.sh` — bats/kustomize/terraform tools aren't installed in
this clusterless session; the full suite runs in GitHub Actions).
