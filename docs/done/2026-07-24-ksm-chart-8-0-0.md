# `kube-state-metrics` chart major bump — `7.8.1` → `8.0.0`

(issue #704; RFC #707 — architect decision 2026-07-24: **Approve.** appVersion
unchanged at `2.19.1` — chart-packaging-only major bump, the entire breaking
surface is the chart dropping its own bundled `CiliumNetworkPolicy` template +
`networkPolicy.flavor: cilium` values key, which
`gitops/platform/observability-ksm.yaml` never sets (verified directly: a `git
diff` between the `kube-state-metrics-7.8.1` and `kube-state-metrics-8.0.0`
chart tags touches only `Chart.yaml`, `README.md`, the removed
`ciliumnetworkpolicy.yaml` template, and a combined 14-line
`networkpolicy.yaml`/`values.yaml` trim — nothing this Application's
`valuesObject` references). No prerequisites — picked up immediately.)

Bumped `gitops/platform/observability-ksm.yaml`'s `targetRevision` from
`7.8.1` to `8.0.0`. Re-verified at pickup time (per the RFC's own acceptance
criteria — don't just trust the cached read): cloned
`prometheus-community/helm-charts` and diffed `charts/kube-state-metrics`
directly between the `kube-state-metrics-7.8.1` and `kube-state-metrics-8.0.0`
git tags a second time — identical result to the RFC's own verification
(5 files, only the `CiliumNetworkPolicy` removal + `Chart.yaml`/`README.md`
housekeeping), and confirmed `kube-state-metrics-8.0.0` is still the newest
chart tag (no `8.0.1`+ has shipped since the RFC was filed).

No other file references the pinned chart version explicitly (no bats
image/chart-pin assertion, no `docs/dependency-tree.md` version mention) —
the existing `tests/securitycontext-observability.bats` assertions check this
Application's own `securityContext`/`containerSecurityContext` YAML keys,
which are untouched by this chart bump (the chart's `values.yaml` diff has no
security-context-related changes), so they continue to pass unmodified.

**ADR-0004 caveat:** this remote clusterless session cannot verify
kube-state-metrics starts cleanly under the re-rendered chart templates on a
real cluster, though the near-empty diff (only a removed, always-disabled
NetworkPolicy template variant) makes that a near-certainty. **Rollback
path:** revert `targetRevision` to `7.8.1`; ArgoCD self-heals within its sync
interval — kube-state-metrics is a stateless read-only metrics exporter with
no persistent state, so a revert recovers instantly with no data loss.

`make ci` passed.
