# cosign sign stage in .gitlab-ci.yml (PR auto/cosign-ci-sign-step)

**ROADMAP item:** 🟢 `cosign sign` stage in `.gitlab-ci.yml` (CHARTER Objective O4, RFC #214 Item 2)

Adds the `sign` stage and `sign-image` job to the capstone GitLab CI pipeline so every
image pushed to Artifactory on `main` is cosign-signed. This is the CI half of Objective
O4 — the in-cluster half is the Kyverno `verifyImages` ClusterPolicy already in
`gitops/kyverno/policies/verify-image-signatures.yaml`.

## Files changed

| File | Change |
|------|--------|
| `.gitlab-ci.yml` | Added `sign` stage; new `sign-image` job (`bitnami/cosign:2`) |
| `tests/cosign-bootstrap.bats` | 9 new structural assertions for the sign stage + job |

## Design decisions

- **Image:** `bitnami/cosign:2` — contains only the cosign binary; minimal attack surface.
- **`COSIGN_EXPERIMENTAL: "0"`** — disables Rekor transparency-log upload. The lab has no
  outbound internet access; omitting this would cause the signing job to fail attempting
  to reach `rekor.sigstore.dev`.
- **`COSIGN_PASSWORD: ""`** — empty string because the keypair generated by
  `make cosign-bootstrap` (`cosign generate-key-pair`) is created with no passphrase.
- **`--allow-insecure-registry`** — Artifactory is served over HTTP (no TLS on the
  `nip.io` route); cosign refuses to push `.sig` OCI tags to plain-HTTP registries by
  default.
- **`$COSIGN_KEY` as a GitLab CI File variable** — GitLab's File-type variable writes the
  content to a temp file and exposes the path; avoids the private key appearing in env.
- **Signs `$CI_COMMIT_SHORT_SHA` tag only** — signs the immutable digest-bound tag, not
  `:latest` (which is mutable and not meaningful for admission verification).
- **`needs: [build-and-push]`** — DAG dependency ensures the image exists before signing.

## Operator steps (one-time setup)

1. Run `make cosign-bootstrap` on the lab host (generates `infra/secrets/cosign/cosign.key`).
2. In GitLab → Settings → CI/CD → Variables, add:
   - Key: `COSIGN_KEY`, Type: **File**, Masked: yes, Protected: yes
   - Value: contents of `infra/secrets/cosign/cosign.key`
3. Push a commit to `main` — the `sign-image` job will push a `.sig` OCI tag alongside
   the image. Once a `.sig` tag is visible in Artifactory, the verifyImages Enforce flip
   (`auto/cosign-enforce-flip`) can be picked up.

## What is NOT in this PR

- The verifyImages `Audit → Enforce` flip (`auto/cosign-enforce-flip`) — that item has
  a maintainer-confirmation prerequisite (at least one `.sig` tag must exist in
  Artifactory before Enforce mode is safe to enable).
