# Bump kube-state-metrics chart `8.3.0` → `8.3.1`

(CHARTER **Core Values** §"Everything as code" + general hardening; executor-fallback
upstream-currency gap analysis 2026-08-17, this run's second pass — reached via
`executor.prompt.md` STEP 6b after the first pass's ACK bump
(`auto/ack-s3-chart-1-10-0`, PR #1203, merged) still left the "Now / next" lane fully
gated (unchanged: the three standing GitLab→Forgejo migration items plus the
`verifyImages` Enforce flip, the O4 CI-rejection-gate, and the legacy capstone
`Deployment` removal, all still gated on unconfirmed maintainer-confirmation issues
#631/#633). **No prerequisites — executor may pick up immediately.**

This cycle also investigated Envoy Gateway `v1.8.3` → `v1.9.0` (a real stable release,
went GA 2026-08-15) but deliberately did **not** bump it: it's this lab's sync-wave-0,
always-on-core north-south ingress control plane (ADR-0008), the fetched upstream
changelog describes multiple breaking changes including a Gateway API CRD version
requirement, and this remote clusterless session has no `helm`/`kubeconform`-against-
live-CRDs way to verify a bump this critical renders cleanly before a live ArgoCD sync
would apply it fleet-wide. Deferred as a documented finding for a live-cluster or
better-tooled session rather than forced through — the same judgment call ADR-0013's
Longhorn hold and ADR-0032's TiDB hold already establish as this repo's convention for
"real upstream release exists, but the blast radius/verification gap says don't
blind-bump it."

Verified directly (not assumed, ADR-0004): the tagged `Chart.yaml` at
`kube-state-metrics-8.3.1` shows `version: "8.3.1"`, `appVersion: "2.19.1"` (unchanged
from `8.3.0` — packaging-only, not a major bump). The upstream release names exactly
one change, "Fix autosharding configuration service"
(prometheus-community/helm-charts#7176, tagged the same day, 2026-08-17). A
byte-level diff of `templates/service.yaml` between the two tags shows the fix's full
scope: the `spec.type`, NodePort, `loadBalancerIP`, and `loadBalancerSourceRanges`
blocks each gain an `autosharding.enabled` guard so a sharded (headless-Service)
deployment renders correctly — this repo's `valuesObject` sets no `autosharding:` key,
so the chart default (`autosharding.enabled: false`) applies and every changed
conditional evaluates identically before and after the bump; the rendered Service for
this Application is unaffected.

Bumped `gitops/platform/observability-ksm.yaml`'s `targetRevision: 8.3.0` → `8.3.1`.
Updated `docs/decisions/adr-0034-lgtmp-observability-stack.md`'s table row + added a
new Re-evaluation log entry (existing entries kept, appended after). Updated
`tests/securitycontext-observability.bats`'s chart-pin assertions (retitled the "pins
chart version" test to `8.3.1`, added a "does not pin the stale 8.3.0 version" guard,
kept the existing 8.0.0/8.1.3/8.2.0 guards). Updated
`docs/dependency-register.md`'s kube-state-metrics row "Last reviewed" cell.

**ADR-0004 caveat:** this remote clusterless session cannot verify kube-state-metrics
still reconciles and reports metrics correctly post-bump on a real cluster. Rollback
path: revert `targetRevision`; ArgoCD re-syncs the prior chart version on the next
reconciliation; no CRD change in this bump, so no data-loss risk.
