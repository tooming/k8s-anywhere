# Bump all four Istio charts `1.30.3` → `1.30.4` (routine currency, real template hardening fix)

(CHARTER **Core Values** §"Everything as code" + general dependency hygiene; upgrade-drafter fallback, executor.prompt.md STEP 6b — this run's ninth cycle: the "Now / next" lane remained fully gated and PLANNER found no ungroomed intake or un-RFC'd 🟡 item.)

Every prior Istio version-currency entry in [ADR-0012](../decisions/adr-0012-istio-ambient-not-sidecar.md)'s Re-evaluation log was CVE-driven — this is the first entry to bump Istio purely on routine currency, matching the non-security-bump pattern this run already established for Kargo/TiDB/Trivy Operator. No explicit "future patch bumps in scope" carve-out exists in ADR-0012's own text (unlike ADR-0031/ADR-0032/ADR-0022), but its binding Decision is the ambient-vs-sidecar architecture choice, not a version pin — nothing in it forbids a routine patch bump. Noted explicitly for transparency about this pattern shift.

Verified directly (not assumed, ADR-0004): the real chart repo's `index.yaml` (`istio-release.storage.googleapis.com/charts/index.yaml`, downloaded directly via `curl` since the file is too large for a single-pass fetch tool) confirms `1.30.4` is the newest stable tag for all four charts (`base`, `cni`, `istiod`, `ztunnel`) — one patch above the pinned `1.30.3`; only `1.31.0-rc.0`/`-beta.*` pre-release tags exist beyond it.

**Method:** downloaded and diffed the actual `.tgz` release assets for all four charts at both versions (the chart repo has no browsable GitHub source tree — same shape as the Trivy Operator chart-releaser pattern). `Chart.yaml` version/appVersion and the bundled image `tag:` default move together in every chart, as expected.

**Real fix found, not just currency.** `istiod`'s diff shows a genuine template-hardening fix across `gateway-injection-template.yaml`, `grpc-agent.yaml`, `kube-gateway.yaml`, and `waypoint.yaml`: several Helm-template annotation lookups (`sidecar.istio.io/proxyImage`, `/logLevel`, `/componentLogLevel`, `/bootstrapOverride`, read from user-settable pod annotations) previously interpolated unquoted into generated YAML — a value containing a YAML-special character could produce malformed or misinterpreted YAML. `1.30.4` wraps every one of these lookups in Helm's `| quote` filter. This lab's `valuesObject`s don't set any of the affected annotations directly, but the templates apply to any ambient waypoint/gateway proxy generated in-cluster, so this is a real, applicable hardening fix.

**Schema compatibility verified.** No `values.yaml` key any of the four `valuesObject`s set (`profile`, `resources.{requests,limits}.{cpu,memory}`) changed shape — confirmed by the full `diff -ru` output.

**This is a heavy/on-demand component** (`make istio-up`/`istio-down`) — zero live-cluster blast radius until the maintainer next brings it up.

Bumped all four `gitops/platform/{istio-base,istio-cni,istiod,ztunnel}.yaml`'s `targetRevision: 1.30.3` → `1.30.4` and their header comments. Appended a new dated entry to ADR-0012's Re-evaluation log. Updated `docs/dependency-register.md`'s Istio and Kiali rows (Kiali's row date was touched only because it shares this ADR — a real, separate currency gap was found for Kiali (`v2.31.0` now exists, pin is `2.30.0`) and flagged for a follow-up cycle rather than bundled into this PR) and `docs/dependency-tree.md`'s citation.

**ADR-0004 caveat.** This remote clusterless session cannot verify the Istio ambient mesh components actually restart cleanly on the new chart versions on a live cluster. Since this is on-demand, that verification happens naturally the next time the maintainer runs `make istio-up`. Rollback path: revert all four `targetRevision` values back to `1.30.3`.
