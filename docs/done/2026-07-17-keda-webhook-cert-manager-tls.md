# KEDA admission webhook TLS — wire to cert-manager's `k8s-lab-ca`

First of ADR-0029's two explicit follow-ups to the already-merged KEDA engine
(`docs/done/2026-07-16-keda-engine.md`). The wave-ordering hazard this item has to
avoid was already found and documented in a prior docs-only pass
(`docs/done/2026-07-16-adr-0029-webhook-tls-wave-ordering.md`), which amended
ADR-0029 with the fix but deliberately deferred building it. This PR builds it.

## What shipped

Patched `gitops/platform/keda.yaml`'s `valuesObject` to add:

```yaml
certificates:
  certManager:
    enabled: true
    issuer:
      generate: false
      name: k8s-lab-ca
      kind: ClusterIssuer
```

replacing the chart's default self-signed cert generation. Verified the exact field
path against the pinned chart's real `values.yaml` (sparse-cloned from
`kedacore/charts` at `release/v2.18`, same technique the engine PR used) — the ADR's
prose already had this right, but it's worth re-confirming rather than assuming stale
prose stayed accurate. Also re-verified the `templates/manager/deployment.yaml`
template logic (`optional: {{ and .Values.certificates.autoGenerated (not
.Values.certificates.certManager.enabled) }}`) directly: with `certManager.enabled:
true`, the expression evaluates to `false` regardless of `autoGenerated`'s value, so
the webhook cert Secret volume does flip from optional to required, exactly as the
prior finding predicted.

**Wave move**: per the ADR's own fix, moved all three KEDA Applications'
`argocd.argoproj.io/sync-wave` from their previous placement (`keda-extras` 0, `keda`
1, `keda-networkpolicy` 4) to `"6"` — alongside `gitops/platform/lab-gateway-certificate.yaml`,
which depends on the same `k8s-lab-ca` `ClusterIssuer` for the same reason. `k8s-lab-ca`
is created by `cert-manager-root-ca` at wave 5, so KEDA now correctly syncs after it.

## Bats coverage

Extended `tests/keda.bats`: updated the three existing wave assertions (`keda-extras`,
`keda`, `keda-networkpolicy`, all now asserting wave 6 instead of their prior
waves); added two new assertions confirming the `certificates.certManager` block
(`enabled: true`, `issuer.generate: false`, `issuer.name: k8s-lab-ca`,
`issuer.kind: ClusterIssuer`).
