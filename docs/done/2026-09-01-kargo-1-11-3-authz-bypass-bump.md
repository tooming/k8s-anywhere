# Bump Kargo chart `1.11.2` → `1.11.3` — real authorization-bypass fix

(CHARTER **Core Values** §"Everything as code" + general hardening; upgrade-drafter fallback, executor.prompt.md STEP 6b — this run's third cycle: the "Now / next" lane remained fully gated (the two GitLab→Forgejo migration items and the capstone-`Deployment`-removal item, all blocked on unconfirmed live-cluster prerequisites — issues #633/#1229/#1345, unchanged since 2026-08-25), PLANNER found no ungroomed intake or un-RFC'd 🟡 item. This cycle's own dependency-currency sweep (following on from this run's earlier Valkey bump, see ADR-0018) surfaced Kargo `1.11.3` as a real candidate.)

Verified directly (not assumed, ADR-0004): the packaged chart's GitHub Packages page (`github.com/akuity/kargo/pkgs/container/kargo-charts%2Fkargo`, since the OCI registry's own `tags/list` endpoint needs registry-auth this sandbox can't complete) lists `1.11.3` published ~8 hours before this check, real digest `sha256:842baea04e91c798f566ed389230d960572bc829c3ce30eedb1e9ee8d29ee57f`. Kargo ships app+chart together from one `Chart.yaml` per release tag, so this is a same-tag app+chart bump.

Commit log (`github.com/akuity/kargo/compare/v1.11.2...v1.11.3`) shows the headline fix is real and security-relevant, not routine currency: `08a4d08` "fix(server): close cluster-scoped authorization bypass in generic resource writes" plus `2aa5fd0` "fix: no authz performed for resource refresh". Checked `github.com/akuity/kargo/security/advisories` directly — no new advisory has been filed for this fix yet (newest entry is still April 2026, unchanged), so this predates formal GHSA/CVE disclosure; treated with the same urgency as a CVE-mentioning release per this repo's own bump-priority convention given the fix's own commit message names an authorization bypass. Also includes two hardening commits ("compile the Helm binary ourselves to reduce vulnerabilities", "update dependencies to reduce vulnerabilities") and two unrelated UI fixes.

`values.yaml` schema re-verified at both tags (`raw.githubusercontent.com/akuity/kargo/{v1.11.2,v1.11.3}/charts/kargo/values.yaml`) for every path this Application sets: `global.securityContext`, `api.{replicas,resources,tls.selfSignedCert,secret}`, `controller.resources`, `webhooksServer.{replicas,resources}` — all present, unchanged structure. Also confirmed `controller.replicas` (set in this Application's `valuesObject` but absent from the chart's own schema at both tags) is a pre-existing harmless no-op, not a regression introduced by this bump — Helm silently ignores values keys with no matching template use. No blast radius either way — Kargo is ON-DEMAND (ADR-0005 budget), so this pin only takes effect on the next `make kargo-up`.

Bumped `gitops/platform/kargo.yaml`'s `targetRevision: 1.11.2` → `1.11.3` and its header comment block. Updated [ADR-0023](../decisions/adr-0023-kargo-promotion-pipeline.md)'s "Chart + version" note and appended a new dated entry to its Re-evaluation log. Updated `tests/kargo.bats`'s two pin assertions (retitled, plus the negative-assertion list extended to include the superseded `1.11.2`). Updated `docs/dependency-tree.md`'s and `docs/dependency-register.md`'s Kargo citations.

**ADR-0004 caveat.** This remote clusterless session cannot verify Kargo actually starts cleanly on the new chart version on a live cluster (Kargo is on-demand, not currently running). No new advisory GHSA/CVE number exists yet for the authz-bypass fix this bump carries — if one is later published against `<=1.11.2`, this pin is already past it. Rollback path: revert `targetRevision` back to `1.11.2`; this Application is not auto-synced (ADR-0005 budget), so a revert takes effect on the next `make kargo-up`.
