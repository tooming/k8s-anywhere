# Bump Kiali chart `2.30.0` → `2.31.0` — 5 real CVE fixes

(CHARTER **Core Values** §"Everything as code" + general hardening; upgrade-drafter fallback, executor.prompt.md STEP 6b — this run's tenth cycle. Found as a bonus finding while re-verifying Kiali's dependency-register row alongside the prior cycle's Istio chart bump (they share [ADR-0012](../decisions/adr-0012-istio-ambient-not-sidecar.md)); flagged there and picked up as its own deliverable this cycle rather than bundled into that PR.)

Verified directly (not assumed, ADR-0004): `kiali/helm-charts`' real tags.atom feed shows `v2.31.0` published 2026-08-24, one release past the pinned `2.30.0`.

**Schema verification method.** `kiali-server/Chart.yaml` and `values.yaml` both carry unresolved `0.0.0`/`${HELM_IMAGE_TAG}` placeholders in git at every tag (version and image tag are injected only at release-packaging time, not committed) — the packaged `.tgz` release asset couldn't be located at a guessable URL in this sandbox, so verification used `git diff v2.30.0 v2.31.0 -- kiali-server/` directly on a real clone of `kiali/helm-charts` instead: **completely empty** — the chart directory is byte-for-byte unchanged between the two tags. No schema risk either way; this lab's `valuesObject` (`auth.strategy`, `external_services.*`, `deployment.resources`) doesn't touch `deployment.image_version` regardless.

**Real content, not just a version label.** A real clone's `git log v2.30.0..v2.31.0` on the `kiali/kiali` app repo (versioning tracks 1:1 with the chart, same as this ADR's 2026-08-04 entry) shows 47 commits, five of them named CVE-driven dependency bumps: axios/undici/immutable, OpenTelemetry-Go (CVE-2026-41178), browserslist (CVE-2026-73089/CVE-2026-73088), golang.org/x/text (CVE-2026-56852), brace-expansion/ip-address/postcss. Also real, non-CVE fixes: several Istio-validation false-positive corrections (KIA0105, KIA0102, KIA1313, and P0/P1 validation checks) and UI bugfixes.

Bumped `gitops/platform/kiali.yaml`'s `targetRevision: 2.30.0` → `2.31.0` and its header comment. Updated `tests/platform.bats`'s pin assertion (retitled, added a negative assertion for the superseded `2.30.0`). Appended a new dated entry to ADR-0012's Re-evaluation log. Updated `docs/dependency-register.md`'s Kiali row and `docs/dependency-tree.md`'s two citations.

**This is a heavy/on-demand component** (`make kiali-up`/`kiali-down`) — zero live-cluster blast radius until the maintainer next brings it up.

**ADR-0004 caveat.** This remote clusterless session cannot verify the Kiali pod actually restarts cleanly on the new chart version on a live cluster, or that its service-graph UI keeps functioning against the new app binary. Since this is on-demand, that verification happens naturally the next time the maintainer runs `make kiali-up`/`make mesh-up`. Rollback path: revert `targetRevision` back to `2.30.0`.
